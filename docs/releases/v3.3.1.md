# EVA Deployer v3.3.1

Summary : Local 설치 준비와 GPU 구성을 자동화하고, NKS Solution-only 설치 지원 및 기존 App·Agent 업그레이드의 안정성을 개선

### Features

- **Local 설치 준비 자동화**: `eva local prepare --config`로 반입한 Bundle의 캐시·Runtime을 배치하고, 필요한 Docker·Harbor와 이미지 게시를 준비합니다. Agent를 선택하면 Qdrant snapshot도 게시하며, 같은 설정 파일로 `eva install --config`를 이어서 실행할 수 있습니다.
- **Airgap Bundle 준비 간소화**: `eva airgap prepare`는 Current Release를 기본으로 사용하고, GPU profile을 지정하면 필요한 자산과 기본 `nvidia-driver-580` 의존 패키지를 준비합니다. Bundle은 실행한 사용자 홈에 저장하며, 완료 후 파일 위치와 반입용 SHA-256을 표시합니다. 다른 드라이버나 Display Mode Selector도 선택해 반입할 수 있습니다.
- **GPU 드라이버·MIG 자동 구성**: Agent·Vision 설치에 GPU preflight를 통합해 필요한 드라이버와 GPU 실행 구성을 준비합니다. RTX PRO 6000 1장은 `eva install configure`에서 MIG 사용 여부를 선택하며, 전체 GPU용 `PRO6000x1`과 MIG 4개용 `PRO6000-MIGx4`를 지원합니다. `eva preflight gpu`는 현재 서버를 준비하고, `--config`를 명시하면 설정된 Agent·Vision 타겟을 준비합니다.
- **NKS Solution-only 설치 지원**: Online Bastion의 기존 configure/install 흐름에서 Cloud(NCP NKS)를 선택하고, kubeconfig로 App·IAM·Agent·Vision을 설치할 수 있습니다. NCP용 Values와 클러스터의 스토리지·GPU 설정을 사용하며, kubeconfig 소유 계정으로 설치·조회·재시도를 실행합니다.
- **외부 App DB 자동 백업**: 기존 외부 MySQL의 접속 정보와 DB 이름을 유지하는 업데이트에서 SQL dump와 필요한 기존 사용자 CSV를 자동 보관합니다. 임시 MySQL client Pod로 백업하고 결과를 검증하며, 이미 IAM 사용자 schema를 사용하는 DB도 SQL dump를 보관합니다.

### Validation & Reliability

- **Local 캐시 검증·재사용**: 같은 Bundle에서 준비한 캐시는 checksum 검증 후 재사용합니다. 준비 기록이 없거나 다른 Bundle의 캐시·손상된 캐시는 덮어쓰지 않고 중단하며, 대상의 Local 준비에는 인터넷 다운로드나 AWS credential을 사용하지 않습니다.
- **GPU 변경 전 보호 강화**: 정상 동작하는 기존 드라이버와 올바른 MIG 구성을 재사용합니다. 다른 MIG 분할이 있거나 변경할 GPU에 workload가 실행 중이면 중단하며, 드라이버·Display Mode 변경 후 재부팅이 필요한 경우 대상 서버의 재부팅과 재실행을 안내합니다.
- **NKS 설치 전 리소스 검증**: API·인증·이미지 접근을 확인하고, workload 변경 전에 최종 manifest의 스토리지·필수 참조·GPU 배치를 검증합니다. 기존 데이터 경로 변경·PVC 축소·확인 가능한 NodePort 충돌은 중단하며, 기존 Helm manifest만 조회해 점검하는 기능도 제공합니다.
- **App 중단 전 DB 검증**: 지원하지 않는 DB 전환과 접속 정보 변경을 App workload 중단 전에 확인합니다. 외부 DB 백업 전후에는 테이블·행 수·schema revision·identity를 비교하고, dump 실패나 데이터 변경이 확인되면 새 App을 기동하지 않습니다.

### Bug Fixes

- **Solution-only 설치 도구 준비 오류 수정**: 기존 k3s 서버에서 실행 계정의 기본 kubeconfig가 없으면 서버의 k3s 설정을 자동 준비합니다. Online 서버의 Solution-only 설치에서 `jq`가 없으면 자동 설치하고, 솔루션 리소스를 변경하기 전에 정상 동작을 검증합니다.
- **App PVC 재사용·Helm 소유권 오류 수정**: 기존 Helm 소유 App PV/PVC를 잘못된 인수 대상으로 판단하던 문제를 수정했습니다. 서버 조회를 허용한 차트 렌더링으로 `lookup`이 재사용하는 영속 저장소를 반영하고, 정확한 Helm 소유권을 확인한 리소스의 잔여 SSA 필드 충돌을 처리하도록 보완했습니다.
- **App NodePort의 공유 Ingress 전환 개선**: 기존 App HTTP NodePort를 같은 공개 포트의 App `/`·IAM `/iam` Ingress로 전환할 수 있도록 보완했습니다. 공개 주소와 무관한 수동 ConfigMap 설정을 보존하고, Ingress 상태 갱신을 외부 변경으로 오인하던 문제를 수정했습니다. 실패 시 확인된 변경의 복구를 시도하며 불일치 필드와 실패 원인을 표시합니다.
- **NKS Values·StorageClass·handoff 오류 수정**: Agent·vLLM·Qdrant·init과 Vision의 NCP Values 참조를 수정했습니다. Agent init은 선택한 NAS·블록 StorageClass 중 없는 것만 생성하고 기존 클래스는 재사용하며, IAM·Argo CD handoff를 설치 계정의 private 경로에 기록하도록 권한 처리를 보완했습니다.
- **NKS Release 선택·과도한 사전 검증 수정**: configure에서 Release 경로를 비우면 공통 Release 선택 규칙을 사용하도록 수정했습니다. Pending PVC·일시적인 GPU 배치·선택적 전역 조회 권한 부족은 경고로 안내하고, manifest의 null 환경변수 목록 때문에 검증이 실패하던 문제를 수정했습니다.
- **NVIDIA APT 서명 키 복구 개선**: NVIDIA Container Toolkit 저장소의 알려진 서명 키 누락을 자동 복구하고 재검증하도록 보완했습니다. Solution-only GPU 감지에서는 설치된 `lspci`를 재사용하며, 도구가 없을 때만 APT와 패키지를 준비합니다.
- **vLLM 캐시 경로 검증 오류 수정**: 환경별 NFS 공유 경로와 기존 vLLM PV의 캐시 경로를 재사용하고, 경로를 지정하지 않은 경우 기본값을 유지하도록 수정했습니다. PV/PVC 검증 오류에는 불일치 항목의 기대값과 실제 값을 표시해 원인을 확인할 수 있습니다.

### Internal Improvements

- **Python 3.12 Runtime 자동 준비**: Runtime bootstrap이 Python 3.12 이상을 자동 선택하고, 호환되는 Python이 없으면 필요한 Python·venv 패키지를 설치한 뒤 Managed Runtime을 구성합니다.
- **k3s kubeconfig 작업 파일 패키징 보완**: 공통 preflight가 사용하는 `src/host-kubeconfig.yaml`을 Infra Release에 포함하고, 해당 파일이 필요한 Release에서 누락을 검증하도록 수정했습니다. 이 파일을 사용하지 않는 이전 Release도 계속 준비할 수 있습니다.
- **설치 회귀 검증 확대**: PR·태그 CI에 Local 준비, GPU 드라이버·MIG 선택, 기존 서버 Solution-only 업그레이드, NKS 설치 흐름과 솔루션 도구 사전 조건의 검증을 보강했습니다. App PVC·DB·공개 포트 전환과 vLLM 캐시 재사용 검증도 확대했습니다.

- **설치 기준**: 서버 설치와 Airgap 준비는 Ubuntu 24.04, `linux/amd64`를 기준으로 하며, 서버의 기본 Kubernetes 환경은 k3s입니다. Managed Runtime은 Python 3.12 이상을 사용하며, 기본 솔루션 배포 버전은 위 표와 같습니다.
- **Local 준비·설치**: 인터넷 준비 서버에서 Bundle을 생성하고 폐쇄망 대상에서 Tool 설치·설정 작성·`eva local prepare`를 완료한 뒤 설치합니다. Agent의 실제 GPU·MIG 구성은 Bundle 준비 시 선택한 profile과 같아야 하며, Release를 바꾸면 새 Bundle로 Local 준비를 다시 실행합니다.
- **NKS 사전 준비**: Cloud의 네트워크·Kubernetes·NCP CSI·GPU·DB·서비스 접속 환경을 먼저 준비하고 `components.infra: false`로 설치합니다. Deployer는 서버용 k3s·드라이버·MIG·NFS 설정을 실행하지 않으며, 기존 Helm Values는 자동 병합하지 않으므로 기존 PVC·경로·용량을 설치 Values에 유지해야 합니다.
- **재설치·업그레이드**: App/IAM 재기동과 공개 포트 전환 중 일시적인 접속 중단이 발생할 수 있습니다. 기존 데이터와 고객사 Values를 확인하고, 수동 ConfigMap 값을 App Helm 업데이트 후에도 유지하려면 `app.additional`에 명시합니다. 외부 DB 자동 백업은 접속 정보·DB 이름이 유지되는 경우에 지원합니다.
- **설정 변경 후 재실행**: 변경한 입력은 새 `eva install --config` 작업으로 적용합니다. `eva retry`는 실패한 작업의 기존 입력 snapshot을 사용합니다. GPU 준비에서 재부팅을 안내한 경우에는 해당 타겟을 재부팅하고 같은 명령을 다시 실행합니다.
