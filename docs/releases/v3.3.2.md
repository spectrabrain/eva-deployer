# EVA Deployer v3.3.2

Summary : Docker 29 환경의 Airgap Bundle 생성 안정성을 개선하고, App·IAM 업데이트 오류 수정 및 Agent 3.3.1 핫픽스를 반영

### Features

- **Agent 3.3.1 반영**: EVA Agent 이미지·Helm chart와 `eva-agent-vllm` Helm chart의 기본 버전을 3.3.1로 업데이트했습니다. 기존 3.3.0 설치 Values를 재사용하는 핫픽스 릴리스에 맞춰 차트·이미지 버전과 Values 버전을 분리하고, Online·NKS 설치와 Airgap 캐시 준비에 반영했습니다.
- **AWS 인증 입력 개선**: Airgap·Remote 준비에서 저장된 AWS 인증을 확인하고, 인증 정보가 없거나 사용할 수 없으면 Access Key ID·Secret Access Key·Region을 입력받습니다. Secret은 숨겨서 입력하며, 검증한 인증은 `/var/lib/eva/credentials/aws_key.ini`에 저장해 재사용합니다. 기본 Region은 `ap-northeast-2`입니다.

### Validation & Reliability

- **이미지 archive 검증 강화**: Docker export가 성공해도 요청한 태그·플랫폼과 config·레이어의 존재 및 무결성을 검증합니다. 압축 blob의 digest와 압축 해제한 레이어의 `rootfs.diff_ids`를 확인하며, 검증이나 복구가 실패한 경우 Bundle을 발행하지 않습니다.
- **실패 로그 보존**: 이미지 export·검증·Registry 복구의 상세 로그를 `/var/log/eva/airgap-prepare/prepare-*/`에 보관하고, 오류 메시지에서 해당 로그 경로를 안내합니다. 로그는 접근 권한을 제한하며, 준비 실패 후에도 남기고 Bundle에는 포함하지 않습니다.

### Bug Fixes

- **Docker 29 이미지 내보내기 호환성 수정**: containerd 이미지 저장소에서 단일 manifest 이미지의 `docker save --platform linux/amd64`가 실패하는 경우를 처리했습니다. 이미지 형식에 맞춰 export를 분리하고, Docker manifest와 OCI index·태그 정보를 유지하면서 하나의 archive로 병합합니다.
- **누락 이미지 구성요소 복구 개선**: Docker가 config·레이어를 생략하고도 export를 성공 처리하는 경우를 검출합니다. 그룹 export 검증 실패 시 이미지별로 로컬 export를 검증해 정상 이미지는 재사용하고, 실패한 이미지만 원본 Registry의 동일 digest로 복구하도록 수정해 불필요한 다운로드를 줄였습니다.
- **zstd 레이어 검증 오류 수정**: zstd로 압축된 OCI 레이어를 압축 상태로 계산해 `rootfs.diff_ids` 불일치로 판단하던 문제를 수정했습니다. 비압축·gzip·zstd 레이어를 구분해 검증하고, 정상 로컬 이미지를 불필요하게 Registry에서 다시 받지 않도록 보완했습니다.
- **Runtime·캐시 패키징 경로 오인 수정**: Ansible Docker collection의 `credentials` Python 코드 폴더를 저장된 인증 정보로 오인해 Bundle 생성이 중단되던 문제를 수정했습니다. Remote와 같이 관리 Runtime·캐시의 허용 루트를 기준으로 패키징하고, 라이브러리·제품 자산 내부의 이름이나 확장자로 인증 파일 여부를 추정하지 않도록 보완했습니다. Local 캐시 복원에도 같은 기준을 적용하며, 허용 루트 밖의 인증·작업 폴더와 렌더링된 Helm Secret은 반입 대상에서 제외합니다.
- **App 업데이트의 추가 롤아웃 방지**: App 기동 후 `imagePullSecrets` 참조 보정으로 추가 롤아웃이 발생하던 경로를 수정했습니다. 최종 Helm 설정에 맞춘 참조 정리를 기존 App 종료 후 새 App 기동 전에 완료해, 이 보정 작업으로 startup 모델 등록이 겹칠 가능성을 줄였습니다.
- **분리된 Ingress 환경의 App·IAM 업데이트 수정**: 별도 Ingress가 App·IAM과 다른 Traefik entrypoint를 명시적으로 사용하는 경우 업데이트를 허용하도록 보완했습니다. 기존 EVA Dock의 HTTPS 443과 App·IAM의 공개 포트처럼 분리된 구성을 보존하며, 다른 Ingress와 entrypoint를 공유하거나 분리 여부를 확인할 수 없는 경우에는 변경 보호를 유지합니다.

### Internal Improvements

- **Airgap·업데이트 회귀 검증 보강**: Docker·OCI archive 병합과 load, 누락 구성요소 복구, zstd 레이어, Runtime 패키징 경로 검증을 보강했습니다. App Secret 참조 정리와 별도 Ingress 보존, Agent 차트·Values 버전 분리도 검증 대상에 추가했습니다.

- **설치 기준**: 서버 설치와 Airgap 준비는 Ubuntu 24.04, `linux/amd64`를 기준으로 하며, 서버의 기본 Kubernetes 환경은 k3s입니다. Managed Runtime은 Python 3.12 이상을 사용합니다.
- **Airgap 수정 적용**: 이미지 export·Runtime 패키징 수정은 Tool에 포함됩니다. 준비 서버에 v3.3.2 Base Release의 Tool을 설치한 뒤 `eva airgap prepare`를 실행해야 하며, 솔루션 자산만 교체하면 설치된 Tool은 갱신되지 않습니다.
- **Bundle 준비 조건**: 준비 서버에는 Docker daemon과 AWS CLI가 필요하며, 원본 Registry·S3·APT에 접근할 수 있어야 합니다. Registry 복구 시 필요한 이미지 구성요소를 다운로드하며, 원본 서비스의 인증·접근 정책과 다운로드 제한이 적용됩니다. Local 대상의 Agent GPU·MIG 구성은 Bundle 준비 시 선택한 profile과 같아야 합니다.
- **Agent 설치 Values**: Agent·vLLM 차트 3.3.1은 기존 3.3.0 설치 Values를 사용합니다. Agent init과 Qdrant 차트 버전은 유지합니다.
