# EVA Deployer v3.3.0

Summary : 단일 설정 파일과 EVA Tool 기반 설치를 도입하고, Online·Remote·Local 배포와 기존 환경 업그레이드의 안정성을 개선

### Features

- **단일 설치 설정 도입**: `eva install configure`에서 설치 환경·대상 서버·컴포넌트·서비스 주소·IAM 연결 방식을 선택하고, 생성한 YAML 하나로 `eva install --config`를 실행할 수 있습니다. inventory, credential, 컴포넌트별 Values는 입력 설정에서 자동 생성합니다.
- **Bastion 다중 타겟 설치 지원**: Online Bastion과 Remote Main의 SSH 설치 흐름을 통합했습니다. 타겟별 SSH·sudo 계정 정보와 설치 구성을 관리하며, 같은 설정 파일에서도 서버마다 설치할 컴포넌트를 선택할 수 있습니다.
- **Remote 자산 준비·공급 자동화**: `eva remote bootstrap`과 `eva remote prepare`로 Main의 Harbor, 이미지·패키지·차트·모델·snapshot 및 Target 전달 자산을 준비합니다. Target에는 준비된 자산과 Harbor 접근 정보를 공급하며 Main의 AWS credential은 전달하지 않습니다.
- **Local Airgap Bundle 생성 지원**: 인터넷 준비 서버에서 `eva airgap prepare`로 선택한 Release와 GPU profile에 필요한 오프라인 자산을 검증해 반입용 Bundle을 생성합니다. 폐쇄망에서는 Bundle을 반입하고 Local Harbor를 통해 설치합니다.
- **Agent·Vision 모델 공급 자동화**: Online에서는 S3에서 모델을 받아 영구 캐시에 저장하고, Remote·Local에서는 준비된 모델 캐시와 Harbor artifact를 사용합니다. Agent/vLLM/Qdrant의 차트·이미지·기본 Values는 선택한 Release를 기준으로 구성합니다.
- **설치 결과·운영 조회 기능 추가**: `eva status`, `eva check`, `eva inspect`, `eva backup`으로 작업 이력·로그·생성 설정·최종 Values·기존 Values 백업을 조회할 수 있습니다. 설치 완료 후와 `eva check`에서 서비스 접속 주소도 확인할 수 있습니다.

### Validation & Reliability

- **설치 입력·Release 검증**: 단일 설정의 필수 입력과 형식을 검증하고, Release metadata와 checksum을 확인한 뒤 설치합니다. 작업별 Plan과 입력 snapshot을 기록해 실행에 사용한 설정을 추적할 수 있습니다.
- **GPU·Argo CD 사전 점검**: GPU driver·MIG 상태를 확인하는 preflight와 Argo CD 관리 해제·연결 검증 절차를 제공합니다. 기존 GitOps 리소스의 소유권을 확인한 뒤 Helm 설치로 전환하도록 정리했습니다.
- **기존 영속 데이터 보존 강화**: Agent·Qdrant·vLLM의 기존 PV/PVC 식별 정보와 연결 관계를 확인하며 재설치·소유권 이전을 수행합니다. Agent 3.3.0에서 더 이상 생성하지 않는 기존 모델 PV/PVC도 업그레이드 과정에서 보존합니다.
- **App DB 이전·사용자 백업 자동화**: 필요한 경우 기존 DB를 비어 있는 대상 DB로 복사하고 검증합니다. 정상적인 기존 대상 DB는 재사용하며, 사용자 schema 변경 전에 로컬 사용자 CSV를 백업합니다. 로컬 license cache와 DB identity 정합화가 필요한 경우 변경 전 DB·cache·identity도 보존합니다.
- **기존 Helm 사용자 Values 백업**: 솔루션과 Agent 의존성 업그레이드 전에 Helm에 저장된 사용자 Values를 별도 영구 경로에 백업합니다. 조회·백업에 실패하면 해당 컴포넌트 설치를 중단하며, 새 설치에 적용한 최종 Values도 별도로 기록합니다.

### Bug Fixes

- **Agent AWS 인증 불일치 수정**: 재설치 시 기존 Kubernetes AWS Secret에 이전 키가 남아 ECR 갱신 Hook이 실패하던 문제를 수정했습니다. 서비스 중지 전에 실제 ECR 인증을 검증하고, 기존 Agent ECR Job을 정리한 뒤 관리되는 Secret을 현재 설정과 동기화합니다. 오래된 세션 토큰은 제거하며 외부에서 제공한 Secret은 유지합니다.
- **Agent ECR 스케줄 복구 오류 수정**: 작업 폴더 정리 과정에서 복구 스크립트가 삭제되어 설치 마지막 단계가 실패하던 문제를 수정했습니다. 스크립트를 영구 경로에 저장하고 복구 실행 전에 다시 준비하며, 설치 완료 또는 일반 오류 발생 시 이번 설치가 중지한 스케줄을 복구합니다.
- **기존 Harbor 연결·재사용 개선**: Docker Compose·k3s로 설치된 기존 Harbor와 HTTP/HTTPS endpoint를 확인하고 재사용하도록 개선했습니다. Remote Target의 k3s registry 연결·인증 설정을 자동 구성하고, 지원되는 Main k3s Harbor의 HTTP 전환에서는 기존 영속 저장소를 유지하며 변경 전 설정을 백업합니다.
- **Remote 이미지 게시 오류 수정**: Docker의 manifest·platform 정보 처리와 Harbor 게시 방식을 보완했습니다. 선택한 `linux/amd64` platform을 기준으로 게시하여 누락된 다른 platform의 콘텐츠 때문에 준비가 실패하던 문제를 수정했습니다.
- **Vision 초기 설치 대기 개선**: 대용량 이미지 다운로드가 기존 대기 시간을 초과해 설치가 실패하던 문제를 개선했습니다. 기본 rollout 대기 시간을 120분으로 늘리고, 실패 시 Pod·컨테이너 상태와 설치 모드에 맞는 진단 정보를 제공합니다.
- **RTX PRO 6000 GPU 인식 수정**: Workstation·Max-Q Workstation 모델명 인식을 보완하여 MIG 구성과 `PRO6000-MIGx4` vLLM profile을 정상 선택하도록 수정했습니다.
- **IAM·App 설정 전달 오류 수정**: 타겟별 Argo CD handoff와 IAM SSO 정보 전달을 보완했습니다. IAM 재설치에서 최신 설정이 반영되도록 재기동하고, 생성된 client Secret 조회를 재시도하며 조회 실패 시 잘못된 handoff를 생성하지 않습니다.
- **HTTP/HTTPS·Traefik 설정 정합성 개선**: 최종 Values에 따른 App/IAM 공개 주소·포트·TLS 설정을 반영하도록 수정했습니다. HTTP 설치의 관리 대상 리다이렉트를 해제하고, HTTPS 설치의 기존 설정과 다른 서비스가 사용하는 listener는 보존합니다. IP 접속용 TLS와 인증서 SAN 검증도 보완했습니다.
- **APT 의존성 준비 오류 개선**: 확인된 APT 저장소·인증 키 구성 문제를 자동 복구한 뒤 의존성을 다시 검증하도록 개선했습니다.

### Internal Improvements

- **배포 소스·환경 설정 구조 분리**: Infra·Solution 설치 소스, Site 입력과 생성 산출물의 경로를 정리했습니다. 버전은 Infra·Solution catalog에서 관리하며 실행 위치와 타겟에 따라 설정이 섞이지 않도록 분리했습니다.
- **Managed Runtime·Current Release 관리**: Ansible과 Kubernetes 도구를 관리되는 Runtime으로 제공하고, Tool installer가 검증한 Release를 Current Release로 등록합니다. SSH 타겟의 도구 준비와 같은 경로에서의 Release 교체도 보완했습니다.
- **대용량 준비 작업 가시성 개선**: 모델·이미지 등 큰 자산을 관리되는 cache에서 재사용하고, Target payload 생성 과정의 파일 수·처리 크기·진행률을 표시하도록 개선했습니다.
- **태그 기반 Base Release 검증**: 태그 CI에서 Go 테스트, ShellCheck, YAML·Ansible 구문 검사와 설치 계약 테스트를 실행합니다. 검증한 소스에서 Tool·Infra·Solution archive, installer, Release metadata와 checksum을 생성합니다.

- **설치 기준**: 기본 Runbook은 Ubuntu 24.04, `linux/amd64`, k3s 환경을 기준으로 합니다. Agent·Vision은 지원되는 GPU와 사전에 준비한 driver·MIG 구성을 확인해야 합니다.
- **기존 인프라 재사용**: 인프라가 준비된 서버는 `components.infra: false`로 솔루션만 업데이트할 수 있습니다. 선택한 솔루션에 필요한 Config 단계와 GPU profile 확인은 계속 수행합니다.
- **재설치·업그레이드**: 설치 과정에서 서비스가 재기동될 수 있습니다. 기존 DB와 모델·Qdrant 데이터의 PV/PVC를 유지하고, 고객사 Values와 인증·라이선스 설정을 확인한 뒤 진행합니다.
- **설정 변경 후 재실행**: 변경한 설정은 `eva install --config`로 새 작업을 시작해야 반영됩니다. `eva retry`는 실패한 작업의 기존 입력 snapshot을 사용합니다. Ctrl+C 등으로 작업을 중단했다면 Helm의 `pending-*` 상태와 중지된 ECR 스케줄을 확인·복구한 뒤 재실행해야 합니다.
